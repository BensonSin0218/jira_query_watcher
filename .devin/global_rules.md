# Git Commit Message Convention

- When creating or amending a Git commit in this repository, use exactly `<type>: <msg>`.
- `<type>` must be one of `feat`, `remove`, `refactor`, `chore`, or `doc`.
- Keep the type lowercase and include exactly one space after the colon.
- Use lowercase for all words in `<msg>` unless a proper noun or standardized acronym requires capitalization, such as `Jira`, `JQL`, `UI`, `FVM`, `macOS`, `Sparkle`, `Flutter`, or `GitHub`.
- Keep `<msg>` concise and descriptive; do not use other type prefixes unless the user explicitly requests an exception.

Examples:

- `feat: add Jira status filtering`
- `remove: delete the obsolete polling option`
- `refactor: simplify watch state persistence`
- `chore: update Flutter dependencies`
- `doc: clarify release instructions`
